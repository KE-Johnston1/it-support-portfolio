# Case Study: Internal Website Connectivity

**Category:** Remote connectivity and application access  
**Environment:** Simulated service desk  
**Skills illustrated:** Reproducing symptoms, network reasoning, verification and documentation

> This is a simulated learning exercise.

## 1. Scenario

A remote user cannot access an internal company website, while public websites remain accessible.

## 2. Initial reasoning

An internal-only website may be reachable only from the corporate network or through an approved VPN connection. Public internet access alone does not prove that internal routing or name resolution is working.

## 3. Troubleshooting steps in the simulation

1. Reproduce the issue using the internal address provided by the scenario.
2. Record the exact error message.
3. Check whether the VPN client is connected.
4. If it is disconnected, connect using the approved simulated workflow.
5. Reload the internal page.
6. Confirm whether the page loads; if it does not, gather additional evidence and escalate.

## 4. Verification and documentation

The issue should be considered resolved only after the internal page loads successfully. Record the initial symptoms, VPN state, action taken, result of the retest and any remaining problem.

## 5. Learning points

- Internal and public resources can have different connectivity requirements.
- Reproducing the reported symptom helps avoid assumptions.
- A successful VPN connection does not automatically prove that every internal service is working.
- Verify the specific resource that failed, not merely the VPN status.
